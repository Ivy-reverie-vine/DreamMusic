# 多源匹配播放实施规格与目标拆分

状态：产品行为已确认，实施中。日期：2026-10-04。规格标签：`ready-for-agent`。T01（Issue #20）兼容身份切片已完成，证据见 [验收记录](../research/issue-20-validation.md)；G1 其他工单及 G2—G8 尚未验收，下方目标清单不据此整项勾选。

## Problem Statement

用户希望一次搜索网易、QQ 和酷狗，同一录音合并展示，点播时尽快获得完整音频；音乐平台无法提供可靠完整版时再尝试 Bilibili，并独立获取原平台或 LRCLIB 歌词。

当前工程已经具备 NightDream 来源注册、api-enhanced / Meting 适配、具体来源资源的 mediaRef、诊断和媒体代理基础，但搜索仍以选定来源或逐源降级为主，播放按一个来源引用解析。非空 URL 不能排除试听；搜索、歌词和播放共用单来源身份也不能准确表达“网易目录条目 + B 站音频 + 网易歌词”。

直接换 URL 会使歌名、封面、收藏、队列和下载入库产生错误关联。既有测试还不能替代对新跨源链路的真实音频和鸿蒙验收。用户需要可靠、可解释的换源行为，而不是搜索到同名结果便播放第一条。

## Solution

保留 DreamMusic 客户端 → NightDream 统一在线入口，由 NightDream 聚合网易、QQ、酷狗候选，保守识别同一录音并合并展示。点播后先解析普通音乐平台候选，找到可靠完整版立即播放；失败或耗尽阶段预算后，在总等待预算内尝试 B 站。

自动换源只接受同一录音且无明显额外片段的完整音频。不确定候选、翻唱、现场和带额外片段的 MV 交给用户手动选择。所有自动解析暂以 10 秒为可调等待目标，超时给出重试或来源选择。

同录音换源保留原曲歌名、歌手、封面与收藏身份，并标明实际播放来源。手动来源只影响当前队列条目；从搜索重新播放时重新解析。歌词按原目录平台 → LRCLIB 获取，有可靠同步歌词才滚动，文本或时间轴不确定时静态显示，缺失不阻塞播放。

第一阶段的新来源只做在线播放。保留既有本地功能与实际网易音频的下载入库，QQ、酷狗、B 站自动下载入库后续设计。

## User Stories

1. 作为听歌用户，我希望一次搜索能查询网易、QQ 和酷狗，以便减少反复切换平台。
2. 作为听歌用户，我希望同一录音只显示一项，以便快速选择。
3. 作为听歌用户，我希望能展开合并结果查看原平台条目，以便知道有哪些候选来源。
4. 作为听歌用户，我希望同名异曲不被合并，以便不会选错歌。
5. 作为听歌用户，我希望 Live、翻唱、重录、伴奏和 Remix 保持区分，以便听到想要的版本。
6. 作为听歌用户，我希望证据不足的结果独立展示，以便自行判断。
7. 作为听歌用户，我希望一个平台失败时仍能看到其他平台结果，以便继续使用搜索。
8. 作为听歌用户，我希望知道搜索是否仅部分成功，以便区分没有歌曲和来源暂时故障。
9. 作为听歌用户，我希望搜索阶段不逐首等待音频解析，以便尽快看到结果。
10. 作为听歌用户，我希望音乐平台有可靠完整版时立即播放，以便减少等待。
11. 作为听歌用户，我希望试听片段不被当作完整版，以便不会播放几十秒就结束。
12. 作为听歌用户，我希望完整性不明时明确保留未知结果，以便不被误导为成功。
13. 作为听歌用户，我希望常规来源不可用时自动尝试 B 站同录音，以便获得更多播放机会。
14. 作为听歌用户，我希望 B 站匹配能识别正确分 P，以便不会播放合集中的另一首歌。
15. 作为听歌用户，我希望带对白、额外前奏或剪辑的 MV 不被自动替换进来，以便保持预期的听歌体验。
16. 作为听歌用户，我希望自动解析有总等待上限，以便不会无限加载。
17. 作为听歌用户，我希望超时或无可靠来源时能重试或手动选源，以便有明确下一步。
18. 作为听歌用户，我希望歌曲开始播放后不会被迟到的高音质结果打断，以便连续收听。
19. 作为听歌用户，我希望实际播放来源可见，以便理解自动换源结果。
20. 作为听歌用户，我希望同录音换源后原曲信息与收藏身份不变，以便保持内容关联稳定。
21. 作为听歌用户，我希望手动选择另一录音时它成为独立条目，以便不会混淆原曲和翻唱。
22. 作为听歌用户，我希望手动来源只作用于当前队列条目，以便一次选择不永久影响后续搜索播放。
23. 作为听歌用户，我希望短时 URL 过期时能够重新解析，以便恢复播放。
24. 作为听歌用户，我希望手动所选资源失效时不会被偷偷换成另一录音，以便保留选择权。
25. 作为听歌用户，我希望切歌后旧请求不再覆盖音频、封面或歌词，以便界面与当前曲目一致。
26. 作为听歌用户，我希望优先使用原目录平台的歌词，以便提高内容匹配准确度。
27. 作为听歌用户，我希望原平台歌词缺失时查询 LRCLIB，以便尽量补全歌词。
28. 作为听歌用户，我希望只有可靠时间轴才同步滚动，以便歌词不会明显错位。
29. 作为听歌用户，我希望文本歌词或时间轴不确定时仍能静态阅读，以便保留可用内容。
30. 作为听歌用户，我希望没有歌词时音乐仍继续播放，以便歌词服务故障不影响听歌。
31. 作为听歌用户，我希望现有本地播放和网易音频下载继续工作，以便不丢失已有能力。
32. 作为听歌用户，我希望网易目录匹配到非网易音频时不会错误写入网易下载链，以便本地音乐库保持正确。
33. 作为听歌用户，我希望鸿蒙后台、锁屏播控和队列切换适用于新播放链路，以便正常使用手机听歌。
34. 作为维护者，我希望来源开关、并发限制和熔断仍然有效，以便隔离单个平台的故障。
35. 作为维护者，我希望区分匹配失败、试听、未知完整性、解析失败和媒体传输失败，以便定位真实问题。
36. 作为维护者，我希望验收分别记录主机测试、浏览器播放和鸿蒙真机结果，以便不把模拟成功当作设备成功。

## Implementation Decisions

### 已确定的架构与行为

- NightDream 是唯一来源编排入口；继续复用 SourceRegistry、MusicOrchestrator、api-enhanced、Meting 和现有媒体代理，不新增一套平行网关，也不修改上游 api-enhanced 的业务实现。
- 保留具体来源资源的 mediaRef 语义；在新编排结果中显式区分目录条目、实际播放来源和歌词来源。不能把 B 站 URL 放进网易引用并声称它仍是网易音频。
- 新契约采用兼容性扩展，旧调用者继续获得原有单来源行为；在目标 G1 中同时落实服务端与客户端模型，不能只写类型而没有可观察往返结果。具体字段名、路由版本和编码方式由实现选择，但不能破坏本规格的身份不变量。
- 新增或扩展搜索聚合、录音匹配、完整性判定、播放解析和歌词解析职责；不要求为了这些名称强行增加五个独立公共模块。优先复用当前可测试边界。
- 匹配使用歌名、演唱者、版本、时长、专辑等证据，保留原平台条目。时长接近或标题相似不单独证明同一录音；不确定时不自动合并或替换。禁止“无合格候选时取第一条”的降级。
- 搜索只取得候选与必要元数据；点播时解析短时音频。聚合需要保留各来源分页与部分成功状态，不能把某个来源的失败或未完成页当作完整搜索结果。
- 用户选定目录条目后，其展示信息保持稳定；较晚搜索结果或实际音频换源不改变当前曲目的身份。合并展示不能消除来源选择和追溯能力。
- 完整性至少区分完整、试听、未知和不可用，保留平台限制字段、资源时长及媒体检查等证据。URL 非空、HTTP 200、Range 前段成功或完整歌词均不能单独证明完整音频。
- 常规平台先尝试，B 站回退使用总预算剩余时间。总自动解析预算暂定 10 秒且可调；不能每个来源各等待 10 秒，也不能耗尽全部时间后才开始 B 站回退。阶段配额通过真实样本校准；播放器后续缓冲单独计时。
- 首个可靠完整版即可起播；成功或取消后终止不再需要的工作，慢结果不得覆盖已开始的播放。每个目标交付时都应遵守请求归属，不能把竞态正确性全部推迟到最终验收。
- B 站资源按 BV/CID 和分 P 处理，不把 UP 主当演唱者。录音不确定或有额外片段时提供手动候选，不能自动套用原录音身份。
- 手动来源选择属于当前队列条目；从搜索发起新的播放时不沿用该选择。手动选择不同或无法确认相同的录音不得建立原曲的永久匹配关系。
- 同录音换源只改实际音频来源，目录信息与收藏身份不变；选择其他录音则成为独立条目。当前支持的收藏行为保持兼容，不扩展跨平台账号收藏同步。
- 旧下载链按实际音频来源限制。目录来自网易但音频来自其他平台时，不自动进入网易数字 ID 入库；真实网易音频与本地播放保留既有功能。第一阶段不要求新的跨源离线数据库迁移。
- 歌词严格按原目录平台 → LRCLIB 处理，不增加其他平台歌词搜索中间层。查询用原曲元数据；同步可信度与内容匹配分开，无法确认时间轴时静态显示。
- 实际 URL 和歌词适配结果分别缓存并带来源关系；资源过期重解析，换源后重新判断歌词时间轴，切歌后旧结果无权更新当前播放。
- 保留现有来源控制、鉴权与媒体传输机制。上游限制应作为不可用结果处理，来源切换不应被误判为用户退出或原有绑定失效。

### 目标拆分与依赖

每项目标必须交付下列可观察结果和对应证据；表中模块名称表示职责归属，不是要求新增独立服务。G 编号是本规格内的实施目标，不是已经创建的子 issue。

| 目标 | 交付结果 | 主要归属 | 前置目标 |
| --- | --- | --- | --- |
| G1 | 来源身份可正确往返，旧单来源调用兼容 | NightDream 契约 + DreamMusic 在线模型 | 无；检查已有引用与代理基础 |
| G2 | 三平台聚合搜索、同录音合并和来源展开可使用 | NightDream 搜索 + DreamMusic 搜索界面 | G1 |
| G3 | 常规平台可靠完整版自动解析与播放，不误入库 | NightDream 播放解析 + DreamMusic 播放接入 | G1、G2 |
| G4 | 音乐平台失败后在预算内回退 B 站 | NightDream B 站适配 + 既有媒体传输 | G3 |
| G5 | 当前队列条目可手动选源，其他录音身份独立 | DreamMusic 队列与来源选择 + NightDream 候选解析 | G2、G4 |
| G6 | 原平台 → LRCLIB 歌词及同步/静态/空结果显示 | NightDream 歌词解析 + DreamMusic 歌词界面 | G1、G3 |
| G7 | 跨源 URL 失效、切歌竞态和既有功能回归闭环 | NightDream 恢复机制 + DreamMusic 播放会话 | G4、G5、G6 |
| G8 | 真实来源、浏览器和鸿蒙端验收证据齐全 | 全链路验收 | G2、G3、G4、G5、G6、G7 |

G1 → G2 → G3 后，G4 与 G6 的前置条件均满足，可以分别实施；G4 → G5；G5 与 G6 完成后进入 G7，最后 G8。本拆分不要求使用子 Agent。

### G1 — 明确来源身份并保持兼容

- 交付：让一个已有来源完成新身份模型的搜索/详情/播放/歌词往返；保留原始来源引用，目录、实际音频和歌词来源可分别表达。定义失败、试听和完整性未知的可观察结果，为后续解析提供一致契约。
- 验收：具体资源引用不改变来源语义；客户端能区分原曲信息和实际音频；未知或非法引用不会串到另一来源；旧单来源请求、现有鉴权和网易绑定行为保持兼容。
- 验收：各在线条目不因数字 ID 相同或共用占位 ID 而互相覆盖；同一录音的展示身份稳定，不以短时 URL 当持久身份。
- 证据：真实 HTTP 入口驱动的契约回归，使用受控上游返回；客户端状态测试验证队列与展示身份。无需为类型声明本身编写镜像测试。

### G2 — 交付聚合搜索与保守合并

- 交付：网易、QQ、酷狗并发搜索；同录音合并、来源可展开；不确定候选独立显示；单源失败和分页未完成保留明确状态。
- 验收：同歌名不同歌手、Live、翻唱、伴奏、重录不错误合并；一个来源超时不吞掉其他结果；后到结果不改变用户已选曲目的身份。
- 验收：搜索不逐曲取播放 URL；各来源分页不串页，重试失败来源不会重复添加已经展示的来源条目；不伪造跨平台完整总数。
- 证据：HTTP 聚合样本与搜索界面交互；成功、空结果、部分失败、重复分页和版本冲突均可复现。

### G3 — 交付常规平台完整版播放

- 交付：在匹配的常规平台候选中查找可靠完整版，选到即起播；暂以 10 秒为总解析目标，明确终止和取消行为；首轮尚未接入 B 站时返回可识别的候选耗尽结果供 G4 扩展。
- 验收：明确试听和完整性未知不记为完整版成功；时长或版本证据不足不自动换源；更慢的高音质结果不能打断已经开始的播放。
- 验收：实际来源与原曲信息同时可见；网易目录匹配到 QQ/酷狗音频时不触发旧网易入库，真实网易音频仍可使用既有下载链。
- 证据：含试听与未知状态的 HTTP 集成场景、客户端下载边界测试，以及至少一个常规来源实际播放样本；外部不可用时保留失败，不能只凭 fixture 关闭实际播放要求。

### G4 — 交付 Bilibili 回退

- 交付：普通来源不可用后生成 B 站候选，取得正确 BV/CID 音频资源；复用媒体传输能力，在同一个总预算内完成回退。
- 验收：普通平台成功时不额外发起 B 站搜索；普通平台阶段不能占满全部回退预算；无可靠候选时返回失败及可选择的手动候选，不拿第一条冒充成功。
- 验收：多分 P 不串曲；UP 主不冒充演唱者；额外前后奏、对白、剪辑、翻唱和未知录音不能自动通过。API 返回音频 URL 与实际可播分别验收。
- 证据：受控 B 站响应的全链路回退测试，以及真实样本的来源、分 P、媒体响应和播放进度记录。真实 B 站不可用时记录阻塞原因，目标不得标成完整通过。

### G5 — 交付手动来源与队列行为

- 交付：用户可在解析失败、超时或来源展开入口选择候选；选择只作用于当前队列条目。
- 验收：同录音只切音频来源，原曲信息与收藏身份不变；另一录音作为独立条目；不确定候选的人工选择不形成已验证同录音关系。
- 验收：从搜索重新播放不继承之前的手动选择；选源期间切歌后旧选择不得覆盖新条目；候选失效时提示重试/重新选择，不静默换成其他录音。
- 证据：真实客户端队列状态测试及 UI 交互截图/记录；测试观察条目身份、展示和播放动作，不依赖按钮内部实现。

### G6 — 交付独立歌词解析与显示降级

- 交付：原目录平台优先，缺失或不适配时查 LRCLIB；返回歌词来源、可用文本及时间轴适配状态，客户端显示同步、静态或暂无歌词。
- 验收：音频来自 B 站时仍可按原目录条目取歌词；原平台成功不请求无必要的 LRCLIB；LRCLIB 查询不使用 UP 主替代歌手。
- 验收：有同步文本不等于时间轴可信；带额外片段的手动 MV 不误滚动；文本歌词、纯音乐标记、空结果和请求失败保留各自语义；所有歌词失败都不阻塞起播。
- 验收：换源重查时间轴关系，切歌后的旧歌词响应无效；缓存不会让不同录音共享错误的同步结论。
- 证据：实际 HTTP 入口的来源顺序/降级场景，歌词显示状态测试和真实 LRCLIB 小样本记录；不以少量命中率宣称中文曲库覆盖率。

### G7 — 完成跨源恢复与既有能力回归

- 交付：围绕已经接通的全链路验证 URL 失效重解析、请求取消、重复回调、队列切换，以及旧单来源和本地路径。
- 验收：短时 URL 过期后重新解析目标资源，循环失败有界；手动来源不被换成另一录音；取消与迟到响应不重复播放、不污染封面/歌词、不重复发起下载。
- 验收：实际网易下载入库和队列替换仍正确；非网易音频不会被网易目录 ID 带进入库；本地离线播放、已有收藏关联与后台播控兼容。
- 验收：来源开关、并发限制、熔断和媒体代理仍作用于新链路；错误可定位到匹配、完整性、解析或传输阶段。
- 证据：扩展现有播放器恢复、媒体代理和下载回归；从受控过期与切歌场景走实际业务逻辑，不只断言内部函数调用次数。

### G8 — 完成真实来源与鸿蒙验收

- 交付：固定样本的可重现验收记录，分别列出主机、真实网络、浏览器与 HarmonyOS 真机结果。
- 验收：普通平台完整版、网易试听被拒后回退、B 站同录音成功、B 站手动候选、歌词降级、10 秒预算、URL 过期和快速切歌均有对应证据；无法获得真实样本的项明确未通过/阻塞。
- 验收：浏览器与鸿蒙记录实际播放状态及进度；鸿蒙单独覆盖后台、锁屏和恢复。完整性需要完整播放或整曲媒体检查证据，前段 Range 成功仅证明可访问性。
- 验收：构建、单元测试、真实网络和设备证据互不替代；既有验收材料只作为历史对照，不能替代本轮新链路证据。
- 交付结论：逐项通过、失败或未执行；没有实际设备证据时不得把本目标或总规格标成完成。

## Testing Decisions

### 主要测试边界

优先使用现有 NightDream 真实 HTTP 路由作为主边界，串起真实引用解析、搜索聚合、匹配、调度、播放与歌词处理；只在第三方请求边界注入受控响应。用客户端实际发送的引用继续请求下一步，而不是每步手写彼此无关的 fixture 身份。

当前已有版本化媒体路由集成测试启动真实 Express 入口，但其中调度器是替身。新跨源验收必须把这部分换为真实编排、仅替换外部请求；不能沿用假调度器后声称完整链路经过了匹配与回退。

客户端补充一个队列/播放会话的公开状态边界，复用已有真实 ArkTS 逻辑加 Kit/网络/存储替身的恢复检查方式。Web 的搜索、播放器和歌词组件测试用于显示与交互反馈；不能作为 HarmonyOS 组件或 AVPlayer 已验证的证据。

### 什么是有价值的测试

- 验证用户可观察结果：返回的来源身份、候选关系、完整性结论、错误状态、队列条目、展示信息、是否发起播放/入库，以及旧请求是否失效。
- 不绑定排序循环、私有辅助函数名、内部缓存实现或各层调用次数；只对来源优先/无不必要回退等外部要求检查边界请求。
- 大多数行为通过主 HTTP 边界覆盖；匹配矩阵和超时/取消竞态可补少量纯逻辑测试，避免为每个模块建立重复的模拟世界。
- 正常用例必须有对应反例：同名错误录音、时长缺失、明确试听、完整性未知、多分 P、MV 对白、来源超时、歌词空结果和迟到响应。
- 时间预算使用可控时间/受控延迟证明有界，真实端到端时延另测；不让确定性回归依赖线上平台状态或真实账号。
- 对此次纯文档产物只检查结构、依赖无环、目标覆盖和发布内容一致，不为文档改动运行全项目业务测试。

### 可复用的测试先例与覆盖模块

| 现有先例 | 本轮用途 |
| --- | --- |
| 版本化媒体 HTTP 路由与媒体契约测试 | 目录/实际音频/歌词身份、旧调用兼容、非法引用与全链路往返 |
| MusicOrchestrator、来源注册与控制测试 | 部分成功、来源禁用、超时、熔断及预算约束 |
| Meting adapter 的真实响应形状 fixture | 正确的 QQ/酷狗字段、歌词/封面与异常响应归一化 |
| 媒体代理、播放诊断和下载测试 | 传输失败、URL 过期、阶段错误与非网易入库隔离 |
| Web SearchOverlay、NowPlaying 与播放器 reducer 测试 | 结果合并、来源显示、歌词降级和稳定队列身份 |
| ArkTS 播放恢复、队列和歌词测试/主机检查 | 切歌竞态、来源选择作用域、重解析和歌词同步状态 |
| 已有隔离音乐测试启动器及真实来源验收脚本 | 小样本真实网络与浏览器证据；按新契约扩展，不能拿旧样本直接过关 |

### 验收层级

1. 确定性行为测试：实际 HTTP 编排、受控上游和客户端公开状态，先证明业务正确。
2. 真实来源验证：记录音频/歌词来源、匹配和完整性证据、解析耗时及失败类别；少量真实样本不代表全曲库。
3. 浏览器验证：真实进入 playing 且进度推进，展示实际来源和歌词状态。
4. HarmonyOS 验证：HAP 构建和相应测试通过后，真机验证 AVPlayer、后台/锁屏、队列和 URL 恢复。此层不能被主机替身或浏览器替代。

本规格沿用上述现有测试边界，以真实业务编排与可观察结果为主；纯逻辑补测和设备验收各自覆盖主 HTTP 边界无法证明的行为。

## Out of Scope

- QQ、酷狗和 B 站音频自动下载入库，以及为此新增的跨源离线迁移。
- 跨平台账号收藏同步、全新的在线收藏持久化体系和永久手动匹配绑定。
- 歌词编辑器、自动对白剪切、自动纠正任意 MV 时间轴。
- 自动接受翻唱/Live/伴奏/重录或未知录音，自动把试听/未知完整性当完整版。
- 等待所有来源后选择最高音质，或播放已开始后因更高音质结果迟到而自动切换。
- 新增 Audius、酷我、YouTube 等本轮三平台搜索之外的聚合目标；已有来源能力保持原状。
- 新建平行网关、把来源逻辑分散到客户端、修改上游项目或重新克隆已有能力库。
- 四个根导航入口重做、无关 UI 重构、依赖升级或代码清理。
- 将旧 issue 自动关闭、宣称旧验证代表新功能成功，或在无设备证据时完成验收。
