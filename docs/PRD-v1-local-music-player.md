# PRD v1:本地离线音乐播放器(IvyReverieMusic)

- 阶段: to-prd(grill-with-docs → **to-prd** → to-issues → implement-review)
- 标签: `ready-for-agent`
- 依据: `CONTEXT.md`(领域词汇表)、`docs/adr/0001`(沙箱导入)、`docs/adr/0002`(/health 契约)、`docs/design/v1-decisions.md`、`docs/design/v1-api-checklist.md`
- 目标环境: HarmonyOS 6.1 / API 23 / ArkTS / 真机 phone

## Problem Statement

鸿蒙 NEXT 上缺少一个纯本地、可离线、尊重用户文件边界的私人音乐播放器:系统没有 Android 式全盘音乐扫描,现有播放器多为在线流媒体。用户需要一个只属于自己设备的应用——把自己挑选的音乐导入后,在任何网络状态下都能可靠播放,具备完整后台播控、播放队列与歌单管理;同时为未来接入自建的 api-enhanced 服务(经 Cloudflare Tunnel 域名)预留干净的连接层。

## Solution

一款纯本地 ArkTS 音乐播放器:

- 用户经系统选择器挑选音频文件/文件夹,应用**复制进应用沙箱**形成音乐库(离线可用是硬保证)
- 完整的标准播放器能力:五页 UI、四种播放模式、持久化队列(可拖拽排序)、断点续播、AVSession 后台播控
- SQLite 管理音轨/专辑/艺术家/歌单/收藏/历史,路径为唯一真相源,启动增量扫描 + 手动重扫
- 网络只做预留:多服务器 Profile + `GET /health` 探活(在线/离线/检查中三态),不调用 api-enhanced 任何业务端点

## User Stories

1. 作为用户,我想要一个首次启动时的引导/空状态页,以便我知道如何把音乐导进来
2. 作为用户,我想要通过系统选择器挑选单个/多个音频文件,以便把想要的歌加入应用
3. 作为用户,我想要通过系统选择器挑选整个文件夹,以便批量导入一整个音乐目录
4. 作为用户,我想要导入过程显示进度(复制中),以便大批量导入时心里有数
5. 作为用户,我想要导入时自动过滤不支持的格式(仅 MP3/AAC(M4A)/FLAC/WAV),以便失败文件不会混进音乐库
6. 作为用户,我想要重复导入同一文件时被去重跳过(按沙箱相对路径),以便音乐库不出现重复音轨
7. 作为用户,我想要导入时自动提取标题/艺术家/专辑/时长/封面,以便音乐库信息完整、封面能展示
8. 作为用户,我想要导入完成后立即在音乐库看到新音轨,以便立刻可以播放
9. 作为用户,我想要设置页有"重新扫描"按钮,以便沙箱文件与数据库不一致时手动修复
10. 作为用户,我想要启动时自动增量扫描,以便外部变化(如残留文件)能自动同步进音乐库
11. 作为用户,我想要从音乐库移除音轨(仅移出库),以便管理不想再看到的内容
12. 作为用户,我想要移除音轨时可选择连同沙箱文件一起删除,以便释放存储空间
13. 作为用户,我想要按"歌曲"视图浏览全部音轨,以便快速找到某首歌
14. 作为用户,我想要按"专辑"视图聚合浏览,以便按专辑听歌
15. 作为用户,我想要按"艺术家"视图聚合浏览,以便按歌手听歌
16. 作为用户,我想要点任意音轨即开始播放(该音轨所在列表自动成为队列),以便符合直觉地听歌
17. 作为用户,我想要在正在播放页看到封面/标题/艺术家/专辑与进度,以便了解当前播放状态
18. 作为用户,我想要拖动进度条跳转、调节音量,以便控制播放位置与响度
19. 作为用户,我想要上一首/下一首/暂停/继续按钮,以便基本控制播放
20. 作为用户,我想要暂停按钮是一个不规则椭圆泡泡(而非方正按钮),以便符合我对 UI 的审美要求
21. 作为用户,我想要四种播放模式(顺序/单曲循环/列表循环/随机)可切换,以便按场景选择播放方式
22. 作为用户,我想要随机模式下"随机"算法不会重复上一首,以便随机体验更自然
23. 作为用户,我想要播完自动切下一首,以便连续听歌
24. 作为用户,我想要播放队列页展示当前队列且可**拖拽调整顺序**,以便自定义听歌顺序
25. 作为用户,我想要队列持久化(重启恢复),以便第二天继续按我的顺序听
26. 作为用户,我想要断点续播(记住上次音轨与进度),以便重开应用从上次位置继续
27. 作为用户,我想要切到后台/锁屏后音乐继续播放,以便正常使用手机其他功能
28. 作为用户,我想要锁屏与控制中心显示封面/标题/上下首/暂停,以便不解锁就能播控
29. 作为用户,我想要耳机线控/蓝牙播控键生效,以便方便地控制播放
30. 作为用户,我想要音轨同目录有同名 .lrc 时显示歌词,以便跟着歌词听/唱
31. 作为用户,我想要没有 .lrc 时不显示歌词区(不报错),以便不打扰
32. 作为用户,我想要收藏音轨(单曲级标记),以便标记喜欢的歌
33. 作为用户,我想要收藏自动聚合进固定歌单"我喜欢的音乐",以便集中听喜欢的歌
34. 作为用户,我想要创建/重命名/删除自建歌单,以便组织自己的音乐
35. 作为用户,我想要把音轨加入/移出自建歌单,以便维护歌单内容
36. 作为用户,我想要播放历史自动记录(上限 500 条),以便回顾听过什么
37. 作为用户,我想要设置页清空播放历史,以便隐私管理
38. 作为用户,我想要设置页手动配置 api-enhanced 服务器地址(别名+URL),以便为未来在线能力做准备
39. 作为用户,我想要保存多条服务器配置并一键切换,以便在不同网络环境(域名/LAN)间切换
40. 作为用户,我想要应用自动探测连接状态(在线/离线/检查中)并静默展示,以便知道当前能否连上我的服务器
41. 作为用户,我想要连接状态变化**不影响**任何本地功能,以便离线时一切照常
42. 作为用户,我想要设置页显示深浅色跟随系统的主题,以便观感与系统一致
43. 作为用户,我想要应用在首次启动/空库/全空歌单等场景有清晰空状态提示,以便不困惑
44. 作为用户,我想要设置页选择一张自定义背景图片,以便播放器界面有自己的氛围
45. 作为用户,我想要界面颜色从背景图片自动提取生成,以便整体观感与我的图一致(视觉个性化核心)
46. 作为用户,我想要正在播放页颜色随当前歌曲封面变化(切歌渐变过渡),以便每首歌都有专属氛围

## Implementation Decisions

### 模块划分(MVVM,依赖单向: view → viewmodel → service → model)

- **viewmodel**: 五页各自状态容器,`@Observed`/`@State` 绑定,不含业务规则
- **service 纯逻辑核心(单测主战场)**: 播放域(队列状态机/播放模式/随机/断点续播)、音乐库域(扫描 diff/去重/格式白名单/导入规划)、连接域(健康状态机/Profile 校验)
- **service 适配层(真机测)**: 播放器会话(封装 AVPlayer+AVSession)、文件系统(封装 fileIo+picker)、HTTP 客户端(封装 http)、库存储(封装 relationalStore)
- **model**: 实体与 DAO;存储 schema 变更集中在库存储适配器内

### 数据库 schema(relationalStore,8 张物理表 = 7 业务表 + 1 关联表)

- `tracks`: 沙箱相对路径(唯一键)、标题、艺术家、专辑、时长、封面路径、收藏标记、导入时间
- `albums` / `artists`: 聚合实体(名称 + 聚合计数)
- `playlists`: 歌单元信息 + `playlist_tracks` 关联表(有序);"我喜欢的音乐"为系统保留歌单,不可删除
- `play_history`: 音轨引用 + 播放时间戳,上限 500 条滚动淘汰
- `favorites`: 音轨引用标记(与"我喜欢的音乐"聚合一致)
- `server_profiles`: 别名、URL、是否当前、是否可用

### 关键行为规则

- **去重键**: 沙箱相对路径(大小写敏感,与文件系统一致)
- **扫描**: 启动时比对"数据库快照 vs 沙箱目录清单"的 diff;新增入库+提元数据,消失的标记为"文件缺失"(保留记录,不自动删)
- **队列语义**: 点歌即把"来源列表"设为队列;队列与当前音轨、播放模式、断点位置一起持久化
- **随机算法**: 洗牌序列持久化,不随机出刚播过的上一首
- **健康检查契约**(ADR-0002): `GET {base}/health`;超时 3s;2xx 且 body 可解析=在线,超时/连接失败/非 2xx=离线,请求中=检查中;启动时 + 每 15s + 手动;失败静默
- **Profile**: 手动多配置;主=Cloudflare Tunnel 域名(HTTPS 公网证书),备=局域网直连(HTTP,明文由系统配置决定)
- **权限**: 仅声明 `ohos.permission.INTERNET` + `ohos.permission.KEEP_BACKGROUND_RUNNING`(均 normal 级 system_grant);`backgroundModes: ["audioPlayback"]` 声明在 **ability 级**(SDK schema 已核实);**无运行时权限弹窗**
- **后台播控**: AVSession 激活 + audioPlayback 长时任务;媒体信息(标题/艺术家/封面/时长/队列)同步到系统会话
- **格式白名单**: MP3 / AAC(M4A) / FLAC / WAV(扩展名→MIME 映射在导入规划器内);实现时对照 Media Kit 官方简介页复核可支持格式
- **歌词**: 仅同目录同名 `.lrc`;读不到则歌词区隐藏
- **主题**: 深浅色跟随系统;主题色可选(默认随系统)
- **动态取色主题**(品牌承诺,见 PRODUCT.md/DESIGN.md): 设置页选背景图 → 复制进沙箱 → ImageKit 缩放读像素 → 纯逻辑取色(量化聚类 + 饱和度/明度钳制)→ 映射 DESIGN.md 角色;蒙层保底,颜色只做强调;无背景图回退铜绿种子色 oklch(0.550 0.095 180);正在播放页从当前封面取色,切歌约 500ms 渐变;取色输出必须满足白字对比度 ≥4.5:1

### 系统能力绑定(全部 `@kit.*`,细节见 API 清单)

CoreFileKit(picker/fileIo)、MediaKit(AVPlayer/AVMetadataExtractor)、AVSessionKit、BackgroundTasksKit、ArkData(relationalStore)、NetworkKit(http)、AbilityKit(context)。

## Testing Decisions

- **好测试的标准**: 只测外部行为(输入→可观察结果),不测实现细节;断言领域术语级结果(如"顺序模式播完最后一首后停住"、"重复路径被去重"、"超时→离线"),不断言内部状态字段
- **单测范围(Hypium 本地)**: 播放域、音乐库域、连接域、**取色引擎**(像素数组→角色色的纯逻辑)四个纯逻辑核心;通过注入适配器接口喂数据,不 mock kit 模块
- **真机测试**: 适配层与全部系统能力(AVPlayer/AVSession/选择器/relationalStore/http),由用户真机执行
- **编译关卡**: `hvigorw assembleHap`(AGENT.md §5)
- **先例**: 仓库为新建工程,仅有模板测试(`entry/src/test/List.test.ets` 等);本 PRD 起建立"纯逻辑进单测、kit 绑定真机测"的惯例

## Out of Scope

- api-enhanced 任何业务端点调用(搜索/在线歌词/在线播放/登录/歌单同步)——仅保留 Profile 与 /health
- 流媒体播放、下载、云盘、评论等在线能力
- 音效/均衡器/音质切换
- 无缝播放(gapless)、倍速播放、睡眠定时
- 歌词编辑/翻译/滚动跟随精细校准
- 多设备同步、账号体系
- 非 phone 形态设备适配(折叠屏/平板暂不承诺)
