# ADR-0007: 在“我的”中统一展示账号级与本机级播放统计

- 日期: 2026-08-23
- 状态: 已接受并已实现
- 关联: `CONTEXT.md`、`docs/TODO.md`、`docs/ui-design.md`

## 背景

播放统计同时存在两个事实来源：DreamMusic 中间层记录账号累计播放数据，设备本地记录播放历史、歌单和收藏等数据。只展示其中一类会让用户误解统计范围；把两类数据混成一个数字又会掩盖来源和可用性差异。

## 决策

本轮 UI 改版统一实现并展示两层统计：

- 账号级统计：来自 DreamMusic 账户，至少包含累计播放时长和已播放歌曲数。
- 本机级统计：来自本机音乐库与播放历史，至少包含播放次数、歌单数和收藏数。

其中“本机播放记录”按 `play_history` 中的事件条数计算；重复播放分别计入，不去重为歌曲数。由于本地历史最多保留 500 条，该指标不宣称为全生命周期累计次数。

本机歌单数只统计用户自建歌单；固定的“我喜欢的音乐”不计入歌单数，收藏数单独统计收藏音轨。

统计详情页标明账号数据来源为 DreamMusic 账户并显示最近同步时间；本机数据标明“本机数据 · 仅此设备”。首页摘要只展示简洁数字，数据解释放在详情页。

统计状态必须区分未登录、加载中、成功且数值为零、请求失败但有上次成功值、请求失败且没有成功值；页面不得通过把缺失值转换为 0 来猜测状态。由独立的 `PlaybackStatsViewModel` 编排账号与本机两类数据。

本机统计只从现有 `play_history`、`playlists` 和 `favorites` 数据派生，不新增统计表或累计统计字段。

页面必须明确标出“账号数据”与“本机数据”。未登录或中间层不可达时，不把账号统计伪装成 0；本机统计仍可独立展示。

账号级统计读取使用 NightDream 的 `GET /auth/profile`；`/auth/me` 继续用于登录门禁、绑定状态和账户摘要。

统计在进入“我的”或统计详情时读取一次，详情页提供手动刷新，不做定时轮询。请求失败时保留当前应用运行期间最近一次成功值并标注“暂时无法更新”；不把账号统计写入本地数据库或普通 preferences，应用重启后重新读取。

账号统计与本机内容并行加载。网络慢或断网时，本机歌单、播放历史、收藏统计和离线播放照常可用；账号统计的加载或失败不得阻塞“我的”页面。

## 理由

- 用户可以同时理解跨设备的账户累计与当前设备的本地使用情况。
- 账号请求失败不应阻塞离线音乐库、歌单和历史。
- 显式来源和可用状态可以避免把“没有数据”“未登录”和“请求失败”混为一谈。

## 后果

- `PlaybackStatsViewModel.ets` 已作为统计状态编排层，ArkUI 页面不直接拼接网络和数据库结果；账号统计通过 `/auth/profile` 读取。
- `DreamMusicAuth.ets` 的账号统计读取与 `LibraryStore.ets` 的本机聚合分别处理加载、失败和空数据状态。
- 本轮 UI 范围扩大到统计摘要和详情；梦点流水归入账户详情，会话列表与凭证管理仍属于设置，不混入统计页面。

## 实施记录

- `PlaybackStatsViewModel.ets` 维护账号级与本机级统计的独立状态，并明确数据来源。
- `DreamMusicAuth.ets` 新增 `profile()`，映射 NightDream `GET /auth/profile` 契约。
- `LibraryStore.ets` 的 `localPlaybackStats()` 从既有 `play_history`、`playlists` 和 `favorites` 派生本机数据，不新增统计表。
- 纯逻辑测试、Hypium 测试和 HAP 构建已通过；统计页面的真机视觉验收仍待执行。
