# ADR-0008: 定时暂停采用设备级截止时间语义

- 日期: 2026-08-23
- 状态: 已接受，待实现
- 关联: `CONTEXT.md`、`docs/TODO.md`、`docs/functional-design.md`

## 背景

DreamMusic 需要在不打扰沉浸播放的前提下支持定时停止。定时暂停必须跨页面、后台和应用重启保持可理解的行为，同时不能改变队列、音乐库或在线音乐来源边界。

## 决策

定时暂停采用设备级播放器状态，不隶属于登录账户、网易云绑定、服务器 Profile 或某一首歌曲。

- 入口和状态展示仅位于“我的 → 设置 → 定时暂停”。
- 首版只提供 30 分钟、60 分钟、120 分钟和关闭四个选择。
- 每次重新选择时，从当前时间重新计算截止时间，不累加时长。
- 使用未来的截止时间表达“到点停止”，用户手动暂停不暂停倒计时。
- 手动切歌、上一首/下一首、重新点播和自然结束都不取消定时暂停。
- 没有当前歌曲时也可以设置；到期前开始播放仍受截止时间约束。
- 到期时正在播放则明确暂停；已经暂停或没有播放则不自动恢复、不切歌、不修改队列。
- 到期后清除定时暂停状态；暂停或后台资源释放失败也不重复触发。
- 应用进入后台、被销毁或重启后保留未到期状态；恢复时以当前时间重新判断。已过期状态只清除，不补执行暂停。

实现上复用现有 `player_state` 持久化播放状态，由播放服务中的纯逻辑 `SleepTimer` 计算截止时间、恢复和剩余时间；到期联动使用显式 `pause()`，不以 `togglePause()` 代替。到期检测同时依赖播放进度、截止时间触发器、前台恢复和应用启动恢复，最终以截止时间判断。

## 理由

- 绝对截止时间不依赖页面是否持续运行，后台、切页和重启后的行为一致。
- 设备级语义符合本地播放器功能，不会因网络账户状态变化而意外取消。
- 设置页单一入口保持正在播放页、队列页和常驻播放条的沉浸与低干扰。
- 复用 `player_state` 避免引入第二套播放持久化来源。
- 显式暂停调用可以避免到期时播放器状态变化导致误恢复播放。

## 后果

- 需要为已有 `player_state` 增加幂等的定时暂停字段迁移，并在保存、恢复和到期清理时保持一致。
- 设置页需要新增播放分组和底部选择面板；其他页面不展示倒计时。
- 播放编排层需要在到期时暂停播放器并让 `BackgroundPlayback` 停止 `audioPlayback` 长时任务。
- 需要新增纯逻辑 Hypium 覆盖固定时长、重复设置、取消、恢复、过期、单次到期和手动暂停语义。
- 仍需真机验收后台播放、锁屏/控制中心状态、重启恢复和资源释放。

## 验收边界

自动化测试验证纯逻辑和状态迁移；真机验证系统播放器、后台生命周期和资源释放。定时暂停不新增网络请求，也不改变在线歌曲的播放、下载或来源策略。
