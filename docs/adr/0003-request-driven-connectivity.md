# ADR-0003: 连接状态改为真实业务请求驱动(取代 /health 探活)

- 日期: 2026-08-16
- 状态: 已接受(grill-with-docs 访谈,用户拍板)
- 关联: ADR-0002(已被本文取代)、CONTEXT.md、docs/PRD-v2.1-dreammusic-middleware.md

## 背景

阶段 v2 进入 api-enhanced 真实业务调用(单曲搜索 / 在线音轨下载 / 在线歌词)。api-enhanced 仓库没有 `/health` 端点,用户拍板**不给服务端补端点**,连接状态不再依赖主动探活。

## 决策

1. **作废 ADR-0002 的 `GET /health` 契约**:客户端不再探活 `/health`;服务端"后续补端点"的计划取消
2. **连接判定**:以最近一次 api-enhanced 业务请求(搜索 / 下载 / 歌词)的成败更新三态状态——成功(2xx 且响应可解析)→ 在线;超时 / 连接失败 / 非 2xx / 关键字段缺失 → 离线;请求进行中 → 检查中
3. **触发时机**:每次业务请求前后更新状态;移除"启动 + 每 15s"轮询(无探活端点,轮询无意义);设置页手动"刷新"改为发起一次轻量请求(如 `GET /search/hot` 或 `/search/default`)验证连通
4. 所有业务请求复用统一 HTTP 网关(baseUrl + 匿名 cookie + 超时 + 错误映射),新增端点不得另起炉灶
5. UI 三态展示保留:设置页连接区 + 在线搜索页离线提示,失败静默不弹窗

## 理由

- 不维护一个"服务端根本不存在"的契约;真实请求的成败就是用户关心的连接事实
- 避免为探活单独造端点与造流量;请求驱动状态下,任何一次业务调用都在刷新真实可用性

## 后果

- 设置页"在线/离线"仅在发生过请求后才有意义;未发生过请求时显示"未检测"
- ADR-0002 中的服务端修改计划(补 /health)取消;局域网直连、多 Profile、统一网关约束不变
