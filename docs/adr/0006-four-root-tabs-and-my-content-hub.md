# ADR-0006: 底部导航收敛为四个一级入口

- 日期: 2026-08-23
- 状态: 已接受并已实现
- 关联: `CONTEXT.md`、`docs/TODO.md`、`docs/ui-design.md`

## 背景

当前应用底部导航同时放置音乐库、正在播放、队列、歌单和我的五个入口。歌单、播放历史、账户和设置都属于用户个人内容或管理内容，但分散在多个一级区域，导致个人内容的入口职责重复。

## 决策

底部导航固定为四个一级入口：

1. 音乐库
2. 正在播放
3. 队列
4. 我的

歌单、播放历史、账户摘要、播放统计和设置归入“我的”的个人内容区域；这些内容的内部浏览不改变底部一级入口的选中状态。

“我的”首页按以下层级组织：账户摘要 → 播放统计 → 我的歌单 → 最近播放 → 设置。

歌单内容包含当前已有的本地歌单、“我喜欢的音乐”和在线网易云歌单/喜欢列表；本地与在线内容分区展示，在线内容独立加载且不得阻塞本地歌单。

公告、签到和发消息属于“我的”的账户内容，不属于设置：签到与今日消息额度放在账户摘要中；公告与消息通过独立快捷卡片进入对应的全页内容。

公告为公开内容，未登录时仍可展示；签到和发消息只要求 DreamMusic 账户认证，不因网易云未绑定或绑定失效而禁用。

账户状态在各页面之间共享：登录、退出、签到、兑换码、发消息和绑定状态变化后，账户摘要、在线资料和登录门禁使用同一份最新账户快照，不由页面各自维护副本。

## 理由

- 队列承担当前播放顺序、拖拽排序和播放模式，仍是跨场景的高频播放区域。
- 歌单和播放历史属于个人内容管理，不需要占用独立的底部入口。
- “我的”可成为个人内容与管理的稳定归属，减少根导航职责重复。

## 后果

- 根导航已从五项迁移为四项，歌单页面不再作为 root tab。
- “我的”已支持总览与内部内容状态，并处理歌单、历史、统计和设置的返回行为。
- 实现复用了现有 ViewModel 和 service，没有复制歌单或历史领域逻辑。

## 实施记录

- `IndexV2.ets` 实现四个一级入口、常驻迷你播放器和统一根级返回处理。
- `MyPageV2.ets` 承载“我的”首页及歌单、历史、统计、账户、公告和设置全页子状态。
- `Navigation.ets` 集中处理根入口、子页面、来源入口和系统返回的状态转换。
- `SettingsPage.ets` 保留账户/连接配置；公告、签到、发消息和兑换码入口已移出设置。
- 自动化构建与测试已通过，鸿蒙真机边缘返回和视觉验收待执行。
