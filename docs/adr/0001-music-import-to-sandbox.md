# ADR-0001: 音乐文件采用"导入复制进应用沙箱"模型

- 日期: 2026-02-13
- 状态: 已接受(用户访谈 Q1)
- 关联: docs/research/harmonyos-official-docs.md §6

## 背景

鸿蒙 NEXT 没有 Android `MediaStore` 式的"扫描全盘 Music 目录"能力。音频文件的来源有三种候选:

1. **导入复制进沙箱**: 用户用系统文件选择器(AudioViewPicker / 文件夹)挑选 → 复制进应用沙箱 → 从沙箱路径播放
2. **选择器 + 持久化授权原位播放**: 不复制,持有 URI 持久化权限直接播原文件
3. **扫描系统公共目录/媒体库**: 自动枚举设备全部音乐(Android 习惯)

## 决策

采用方案 1: **导入复制进应用沙箱**。

## 理由

- 社区实测表明 AVPlayer 只能播放网络 URL 与应用沙箱路径,方案 2 的持久化 URI 可能无法直接喂给 AVPlayer(待真机最终验证)
- 方案 2 的 URI 在用户移动/删除文件后失效,需额外失效处理;方案 3 在 NEXT 上公共目录不可自由枚举,基本不可行
- 方案 1 的路径完全由应用掌控,元数据/封面/歌词缓存全部挂在同一个文件树下,离线确定性最强
- 代价(双倍存储占用、导入耗时)对"私人精选本地库"场景可接受

## 后果

- 扫描的定义变为"比对沙箱音乐目录与数据库",而非遍历设备
- 数据库以**沙箱相对路径**为音轨唯一键
- 移除音轨时可选择"仅移出音乐库"或"连同文件删除"(待实现时细化)
- 若真机验证发现 AVPlayer 支持持久化 URI,方案 2 可作为后续优化(免复制),但不改变本决策的数据库与播放管线设计
