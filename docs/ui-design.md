# DreamMusic UI 信息架构设计方案

> 状态：已实现，待真机验收（2026-08-23）。底部导航采用四个一级入口；“我的”内部内容统一使用全页子状态，首页层级为账户摘要、播放统计、我的歌单、最近播放、设置；公告、签到、发消息已明确归入“我的”账户内容，不属于设置。

## 1. 设计目标

实施前底部导航有五个一级入口：

```text
音乐库 / 正在播放 / 队列 / 歌单 / 我的
```

参考鸿蒙手机版 QQ 的布局收敛思路：底部导航只保留高频、跨场景的核心区域，低频管理内容集中到“我的”页面，避免底部入口过多、页面职责重复。

本方案将底部导航从 5 个缩减为 4 个：

```text
音乐库 / 正在播放 / 队列 / 我的
```

不复刻 QQ 的具体视觉，而是借鉴其信息架构原则：

- 底部一级入口数量受控；
- 个人内容、历史和设置集中到“我的”；
- 高频操作留在底部，低频管理操作进入二级内容；
- 页面之间保持稳定的主导航位置。

## 2. 新底部导航

| 顺序 | 入口 | 核心职责 | 原页面 |
|---:|---|---|---|
| 1 | 音乐库 | 本地歌曲、专辑、艺术家、在线搜索和导入 | 保留 `MusicLibraryPage` |
| 2 | 正在播放 | 当前歌曲、歌词、播放控制和封面沉浸体验 | 保留 `NowPlayingPage` |
| 3 | 队列 | 当前播放队列、拖拽排序、播放模式和移除 | 保留 `QueuePage` |
| 4 | 我的 | 歌单、播放历史、账户和设置 | 合并 `MyPage`、`PlaylistsPage`、`SettingsPage` |

### 为什么保留“队列”

队列不是低频资料管理页，它承担：

- 当前播放顺序查看；
- 拖拽调整顺序；
- 播放模式切换；
- 删除队列条目；
- 当前曲目状态反馈。

因此第一阶段只移除“歌单”底部入口，不把队列强行塞入正在播放页。这样可以减少一级入口，同时避免把拖拽队列和沉浸式播放页混在一起。

## 3. “我的”页面新结构

“我的”从当前的账户/历史入口升级为个人内容中心：

```text
我的
├─ 账户摘要
│  ├─ 登录状态
│  ├─ 梦点/绑定状态摘要
│  └─ 设置入口
├─ 我的歌单
│  ├─ 我喜欢的音乐
│  ├─ 自建歌单列表
│  ├─ 新建歌单
│  └─ 查看全部
├─ 最近播放
│  ├─ 最近播放摘要
│  └─ 查看全部
└─ 其他管理
   └─ 设置
```

### 3.1 账户摘要

保留当前 `MyPage` 的账户卡片，作为“我的”页面顶部内容：

- 未登录：显示“本地音乐”和登录引导；
- 已登录：显示账户、梦点和绑定状态；
- 设置按钮进入设置内容；
- 不把复杂账户操作直接铺在首页，避免账户信息压过歌单内容。

### 3.2 我的歌单

歌单是“我的”页面的主要内容区，应放在账户摘要之后、播放历史之前。

默认展示：

- 我喜欢的音乐；
- 最近使用或最近创建的自建歌单；
- “查看全部歌单”；
- “新建歌单”。

歌单行继续显示封面/占位图、名称和歌曲数量。点击后进入“我的”内部的歌单详情状态，不切换底部一级入口。

### 3.3 歌单详情

歌单详情作为 `MyPage` 的内部子状态：

```text
我的根页面
  → 歌单详情
      → 歌单歌曲列表
      → 点歌播放
      → 添加歌曲
      → 移除歌曲
      → 重命名/删除自建歌单
```

详情页应提供明确的返回操作，返回后仍然位于“我的”页面，不改变底部选中项。

系统保留歌单“我喜欢的音乐”继续遵守现有规则：不可删除、不可重命名，但可以播放和查看歌曲。

### 3.4 最近播放

播放历史不再作为单独底部入口，继续放在“我的”页面：

- 首页显示最近几首摘要；
- 点击“查看全部”进入内部历史详情；
- 支持播放历史中的歌曲；
- 支持清空历史；
- 空状态提供回到音乐库的引导。

### 3.5 详细页面布局

“我的”采用单页纵向滚动总览，不把所有内容平铺成同等权重的菜单。页面按“身份 → 数据 → 内容 → 管理”的顺序组织：

```text
┌─────────────────────────────┐
│ 我的                    设置 │  页面标题
├─────────────────────────────┤
│ 账户摘要                     │  登录/绑定/梦点
├─────────────────────────────┤
│ 播放统计                     │  账号级 + 本机级
├─────────────────────────────┤
│ 我的歌单                 查看全部 │
│ 我喜欢的音乐                 │
│ 自建歌单                     │
├─────────────────────────────┤
│ 最近播放                 查看全部 │
│ 最近歌曲摘要                 │
├─────────────────────────────┤
│ 设置                         │  进入设置子页面/弹层
└─────────────────────────────┘
```

布局规则：

- 页面整体只有一个纵向 Scroll；
- “设置”作为页面标题栏右侧快捷入口，同时在底部管理分组保留一行入口，避免用户找不到；
- 歌单、统计、历史均采用分组卡片，不使用三个并列大按钮；
- 每个分组只展示摘要，复杂内容进入内部详情页；
- 账户状态不占据首屏大面积，避免“我的”变成账户后台；
- 页面顶部保留足够安全区，底部避让常驻播放条和玻璃导航栏。

### 3.6 账户摘要区

账户摘要是“我的”页面第一张卡片，但保持紧凑。

#### 未登录

显示：

- 本地音乐；
- “登录后使用在线搜索、网易云歌单和账户统计”；
- 登录按钮。

本地歌单、播放历史和本机统计仍可正常查看，不因未登录而隐藏。

#### 已登录

显示：

- DreamMusic 用户名；
- 网易云绑定状态；
- 梦点余额；
- 今日签到/消息额度的简短摘要；
- 设置快捷入口。

公告、签到和发消息不放在设置页；它们的具体入口位置待本轮信息架构确认。

本轮信息架构确认：签到按钮与今日消息额度放在账户摘要中；公告与消息使用账户摘要下方的独立快捷卡片，并进入“我的”内部全页内容。

账户卡片不直接展示会话列表等详细账户管理内容；会话、凭证和登录安全进入设置子页面，梦点流水进入账户详情。

梦点余额相关操作不放在设置：账户摘要进入“账户详情”全页，兑换码在其中完成；账户摘要本身只展示余额和入口。

账户详情同时展示最近梦点流水（只读）；会话列表、凭证和登录安全仍属于设置。

账户摘要保持紧凑，只展示用户名、绑定状态、梦点余额、签到状态、今日消息额度，以及“账户详情”“公告与消息”“设置”入口；兑换码、梦点流水、发消息表单、会话列表和二维码绑定流程均进入对应全页。

登录、退出、签到、兑换码、发消息和绑定状态变化后，账户摘要、在线资料和登录门禁必须即时使用同一份最新账户快照，不允许页面各自维护梦点、绑定或消息次数副本。

#### 绑定失效或账户不可用

- 绑定失效：显示“重新绑定网易云”；
- 账户被禁用：显示状态提示，不展示会导致失败的操作按钮；
- NightDream 暂时不可达：保留本地内容，账户统计标记为“暂时无法更新”，不阻塞页面。

### 3.7 公告、签到与消息

- 签到作为账户摘要中的直接操作：未签到时显示“签到 +10”，点击后直接请求；请求中禁止重复点击，成功后更新梦点并显示“今日已签到”，已签到时显示不可重复操作的状态。
- 今日消息额度作为账户摘要中的简短状态，并提供进入发消息内容的入口。
- 公告与发消息不放在设置页；账户摘要下方提供“公告与消息”快捷卡片，点击进入“我的”内部全页内容。
- 公告使用公开接口，未登录时仍可展示摘要；签到和发消息需要登录，未登录时显示登录引导而不展示可执行操作。
- 公告加载失败只在快捷卡片内显示状态，不阻塞本地内容。
- 已登录但未绑定或绑定失效时，签到和发消息仍可用；绑定状态只限制在线音乐及网易云个人资料能力。

“公告与消息”是一个“我的”内部综合全页：上半区展示公告列表，下半区展示发消息表单与今日额度；未登录时公告仍可读，发消息区显示登录引导。

发消息表单默认折叠，只展示今日使用/剩余次数与当前梦点余额；点击后在同一页面内展开。登录失效、梦点不足或达到每日 3 次时显示对应状态并禁用提交。

公告本轮不设计已读/未读状态或角标；页面只展示当前已发布且未过期的公告。

“我的”首页的公告与消息快捷卡片只展示公告数量和最新一条标题；点击进入完整公告列表与发消息表单。无公告时仍保留入口并显示“暂无公告”，加载中或失败只影响该卡片。

## 4. 播放统计详细方案

播放统计采用“账号级统计 + 本机统计”双层结构，必须在 UI 中明确标记数据来源。

### 4.1 统计卡片位置

播放统计位于账户摘要之后、歌单之前，是“我的”页面第二个主要分组。

卡片顶部：

```text
播放统计                                      查看详情
```

卡片主体分成上下两层：

```text
账号累计                                    本机概览
累计播放时长       播放歌曲数                本机播放次数   最近播放
```

不使用复杂图表作为首屏主视觉；首屏重点是能快速读懂的数字和最近状态。

### 4.2 账号级统计

账号级统计来自 NightDream，是服务器账户数据：

- 累计播放时长 `playSeconds`；
- 已播放歌曲数 `playedSongCount`。

显示文案必须带来源提示：

```text
账号累计
来自 DreamMusic 账户
```

未登录时：

- 不显示伪造的 0；
- 显示“登录后记录账号播放统计”；
- 不影响本机统计显示。

服务端数据加载失败时：

- 保留上一次成功值；
- 显示“暂时无法更新”；
- 提供轻量刷新入口；
- 不阻塞歌单、历史和本地播放。

账号统计在进入“我的”或统计详情时读取一次，详情页支持手动刷新，不做定时轮询；上一次成功值仅保留在当前运行期间，应用重启后重新读取。

### 4.3 本机级统计

本机统计来自设备本地 SQLite 和播放器状态，不上传为前提。

第一阶段显示：

- 本机播放记录：按 `play_history` 事件条数统计，重复播放分别计入；由于历史上限为 500 条，不称为全生命周期累计播放次数；
- 本机歌单数：本地自建歌单数量；
- 本机收藏数：`favorites` 中的收藏音轨数量，固定的“我喜欢的音乐”不重复计入歌单数；
- 最近播放：直接复用 `play_history`。

本机累计播放时长不能简单用歌曲总时长代替真实收听时长。若后续需要展示，应新增本地播放秒数累计器，按实际播放进度增量记录；在此能力完成前不显示“本机累计播放时长”这个名称。

本机统计显示来源：

```text
本机数据 · 仅此设备
```

### 4.4 统计详情页

点击“查看详情”进入“播放统计”内部页面，底部仍选中“我的”。详情页分为：

1. 账号统计：累计时长、歌曲数、最近同步时间；
2. 本机统计：播放次数、歌单数、收藏数；
3. 统计说明：解释账号数据和本机数据的区别；
4. 刷新账号统计：仅刷新 NightDream 数据，不重算本地数据；
5. 登录引导：未登录时显示。

详情页暂不加入排行榜、曲风分析、图表趋势和社交比较，避免扩大产品范围。

详情页标明账号数据来源为 DreamMusic 账户并显示最近同步时间；本机数据标明“本机数据 · 仅此设备”。首页摘要只展示简洁数字，数据解释放在详情页。

### 4.5 播放统计数据接口

页面层不直接调用网络接口或数据库。建议由 `MyPageViewModel` 或独立的 `PlaybackStatsViewModel` 编排：

```text
MyPage
  → PlaybackStatsViewModel
      ├─ DreamMusicAuth.profile() → GET /auth/profile / 账号统计读取
      ├─ LibraryStore 本机聚合
      └─ PlayerViewModel 当前播放状态
```

统计模型应区分来源：

```ts
interface PlaybackStatsSummary {
  account: {
    available: boolean;
    playSeconds: number;
    playedSongCount: number;
    updatedAt: number;
  };
  device: {
    playCount: number;
    playlistCount: number;
    favoriteCount: number;
    recentTracks: Track[];
  };
}
```

该模型的接口不应让 UI 猜测“0”是没有数据还是网络失败，应使用 `available` 和错误状态明确区分。

状态还必须区分未登录、加载中、成功且为 0、失败但有上次成功值、失败且无成功值；由独立 `PlaybackStatsViewModel` 统一编排账号和本机数据。

## 5. 我的歌单详细方案

### 5.1 首屏歌单区

歌单区位于统计卡片之后：

```text
我的歌单                         查看全部
┌─────────────────────────────┐
│ ♡ 我喜欢的音乐          N 首 │  固定置顶
│   最近使用的自建歌单          │
│   最近创建的自建歌单          │
│ ＋ 新建歌单                   │
└─────────────────────────────┘
```

推荐首屏最多展示：

- 固定的“我喜欢的音乐”；
- 2 个自建歌单；
- 新建歌单入口。

其他歌单通过“查看全部”进入完整列表，避免歌单较多时把播放统计和设置推到很下面。

### 5.2 全部歌单页

全部歌单是“我的”内部子页面，支持：

- 查看全部自建歌单；
- 新建歌单；
- 重命名；
- 删除；
- 进入详情；
- 继续显示固定的“我喜欢的音乐”。

固定歌单使用明确的系统图标或心形 SymbolGlyph，不提供删除和重命名操作。

### 5.3 歌单详情页

歌单详情沿用现有 `PlaylistsPage` 的领域操作，但迁移到“我的”子页面：

- 标题栏左侧返回；
- 中间显示歌单名称和歌曲数量；
- 右侧提供播放全部或更多操作；
- 列表行支持播放；
- 自建歌单支持移除歌曲；
- “我喜欢的音乐”支持播放和取消收藏，但不显示删除歌单操作。

歌曲添加入口仍来自音乐库歌曲操作“添加到歌单”，不要求用户先返回“我的”。

### 5.4 在线个人资料

当前 `PlaylistsPage` 中的在线网易云歌单与在线“我喜欢的音乐”一并迁移到“我的”，但与本地歌单分区展示。在线资料独立加载；未登录、绑定失效或 NightDream 不可达时，在线区显示对应状态，本地歌单和离线播放不受影响。

## 6. 最近播放详细方案

最近播放作为“我的”页面的第三个内容分组：

- 首屏最多展示 3 条；
- 显示封面、歌名、艺术家；
- 点击“查看全部”进入历史详情；
- 点击歌曲直接使用历史列表作为队列播放；
- 缺失文件显示不可播放状态，不让页面崩溃；
- 清空操作只放在历史详情页，避免误触。

最近播放和本机统计共享 `PlaylistsViewModel` / `LibraryStore` 数据，不重复建立历史读取逻辑。

## 7. 设置区详细方案

设置不与歌单混成一组，而是作为“我的”页面末尾的管理区域，同时保留顶部快捷入口。

```text
设置
├─ 账户与绑定
├─ 定时暂停
├─ 主题与背景
├─ 本地音乐库
├─ NightDream 服务器
└─ 关于与诊断
```

设置页面作为“我的”的独立全屏子页面，保持单页纵向滚动与分组结构，继续承担账户认证/绑定、主题与背景、本地音乐库、服务器 Profile/连接状态、关于与诊断；定时暂停仍是后续功能，不因本轮 UI 迁移提前实现。

设置中的账户区只负责登录、注册、退出登录、网易云绑定/重新绑定，以及会话和凭证等账户管理；签到、梦点操作、发消息和公告不属于设置。

定时暂停严格只在：

```text
我的 → 设置 → 定时暂停
```

显示，不在播放统计卡片或正在播放页显示。

## 8. 滚动和信息密度

“我的”内容较多，必须按分组渐进披露：

- 账户卡片紧凑；
- 统计卡片只展示摘要数字；
- 歌单首屏限制数量；
- 历史首屏限制数量；
- 详情内容通过子页面承载；
- 设置不在首页展开全部表单。

当内容为空时，分组仍保留标题和下一步动作，不让页面出现大面积无意义空白。

页面滚动时：

- 底部播放条保持可访问；
- 底部玻璃导航保持固定；
- 不在滚动过程中自动隐藏导航；
- 内部歌单/统计/历史详情使用独立滚动容器时，避免与外层 Scroll 嵌套造成手势冲突。

## 9. 实现拆分

| 模块 | 设计职责 |

不得把歌单、历史和统计逻辑直接写进 ArkUI `build()`；页面只消费 ViewModel 输出的状态。

### RootTab 与子状态

```text
RootTab
├─ LIBRARY
├─ NOW_PLAYING
├─ QUEUE
└─ MY
   ├─ HOME
   ├─ PLAYLIST_DETAIL
   ├─ HISTORY_DETAIL
   ├─ STATS_DETAIL
   └─ SETTINGS
```

底部导航只改变 `RootTab`；“我的”内部子状态不改变底部选中项。由“我的”内部进入歌单、历史、统计和设置时返回“我的”根页面；从其他一级入口深链进入时，系统返回回到来源入口。

在线操作触发登录时，登录成功后保留原一级入口、搜索关键词和浏览位置；只关闭登录层，不自动重放播放、下载或其他原操作，用户再次点击后执行。

从“我的”子页面切换到其他一级入口后，再次点击“我的”时回到“我的”首页并清除旧子页面状态；外部深链仍可直接打开指定子页面。

常驻播放条与底部玻璃导航在“我的”及其全部子页面中保持固定可见；子页面内容在中间区域独立滚动，不覆盖播放控制或底部导航。

## 12. 视觉与交互原则

- 底部导航使用 4 个等宽入口、玻璃底栏和 SymbolGlyph；
- “我的”页面分组卡片保持相同圆角、间距和主题 token；
- 统计卡片强调数字可读性，不使用高饱和图表抢占歌单内容；
- 歌单封面、收藏心形和播放状态使用统一图标体系；
- 设置入口属于管理内容，视觉权重低于歌单和统计；
- 空状态必须提供下一步动作，例如“去音乐库导入歌曲”“去音乐库收藏歌曲”“新建歌单”；
- 所有子页面返回、弹层关闭和系统返回手势都回到“我的”根页面；
- 从其他一级入口触发的深链应直达目标子页面；例如音乐库进入服务器配置时直达“我的 → 设置”，在线操作未登录时直达登录引导，兑换码直达“我的 → 账户详情”；
- 保留底部播放条和底部导航，不在滚动过程中自动隐藏；
- 避免外层“我的” Scroll 与歌单/历史/统计详情 Scroll 产生嵌套手势冲突。
